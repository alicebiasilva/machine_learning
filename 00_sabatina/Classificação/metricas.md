# Métricas de classificação

### 1. O que é uma matriz de confusão e o que significam TP, TN, FP e FN?

A matriz de confusão é uma forma de comparar as previsões de um modelo de classificação com os valores reais, permitindo entender não apenas quantos casos o modelo acertou, mas também que tipo de erro ele cometeu. Em um problema binário, temos quatro possibilidades: True Positive (TP) acontece quando o modelo prevê a classe positiva e ela realmente é positiva, como identificar corretamente uma fraude; True Negative (TN) acontece quando o modelo prevê a classe negativa e ela realmente é negativa, como classificar corretamente uma transação legítima; False Positive (FP) acontece quando o modelo prevê positivo, mas o verdadeiro valor é negativo — o chamado erro tipo I, como bloquear uma transação legítima pensando que é fraude; e False Negative (FN) acontece quando o modelo prevê negativo, mas o verdadeiro valor é positivo — o erro tipo II, como deixar passar uma fraude. A partir desses quatro valores construímos praticamente todas as principais métricas de classificação: por exemplo, Accuracy considera (TP + TN) sobre o total, Precision mede TP/(TP + FP), perguntando “entre os casos que o modelo classificou como positivos, quantos realmente eram positivos?”, enquanto Recall mede TP/(TP + FN), perguntando “entre todos os casos que realmente eram positivos, quantos o modelo conseguiu encontrar?”. A importância da matriz de confusão é que ela permite enxergar o trade-off entre diferentes tipos de erro; em um detector de fraude, por exemplo, um FP pode significar bloquear um cliente legítimo, enquanto um FN pode significar deixar uma fraude passar, e o custo desses dois erros pode ser completamente diferente. Portanto, a matriz de confusão é a base para interpretar o comportamento de um classificador: TP e TN são acertos, FP e FN são erros, e a importância de cada um depende do contexto do problema.

### 2. O que são Accuracy, Precision, Recall e F1-score? Qual a diferença entre elas?

Accuracy, Precision, Recall e F1-score são métricas diferentes para avaliar um classificador, e a principal diferença entre elas é quais tipos de acerto e erro elas priorizam. A Accuracy mede a proporção de todas as previsões que o modelo acertou, Accuracy = (TP + TN)/(TP + TN + FP + FN), então responde à pergunta: “de tudo que o modelo classificou, qual percentual estava correto?”. A Precision olha apenas para as previsões positivas e pergunta: “quando o modelo disse que é positivo, com que frequência ele estava certo?”, sendo Precision = TP/(TP + FP); portanto, ela é especialmente importante quando falsos positivos são custosos. O Recall, também chamado de sensibilidade, olha para todos os casos que realmente são positivos e pergunta: “dos positivos que existiam, quantos o modelo conseguiu encontrar?”, sendo Recall = TP/(TP + FN); portanto, é importante quando falsos negativos são mais preocupantes. Já o F1-score é a média harmônica entre Precision e Recall, F1 = 2 × Precision × Recall/(Precision + Recall), sendo útil quando queremos um equilíbrio entre os dois e não queremos que uma métrica muito alta compense uma muito baixa. Um exemplo ajuda: imagine um modelo de detecção de fraude. Se o modelo for extremamente conservador e quase nunca disser “fraude”, ele pode ter Precision alta, porque quando acusa fraude geralmente está certo, mas terá Recall baixo, porque deixará muitas fraudes passarem. Se fizermos o contrário e o modelo marcar quase tudo como fraude, teremos Recall alto, mas provavelmente Precision baixa, porque muitos clientes legítimos serão classificados como fraudadores. A Accuracy pode ser particularmente enganosa em bases desbalanceadas: se apenas 1% das transações forem fraude, um modelo que classifica absolutamente tudo como “não fraude” terá 99% de Accuracy, mas Recall de 0% para fraude. Por isso, não existe uma métrica universalmente melhor: Accuracy mede acerto geral; Precision mede a qualidade das previsões positivas; Recall mede a capacidade de encontrar os positivos; e F1 busca equilibrar Precision e Recall. A escolha deve depender do custo relativo dos falsos positivos e falsos negativos no problema de negócio.

### 3. Qual a diferença entre Precision e Recall e como decidir qual priorizar?

A diferença fundamental entre Precision e Recall está na pergunta que cada uma responde: Precision olha para aquilo que o modelo previu como positivo, enquanto Recall olha para aquilo que realmente era positivo. A Precision é TP/(TP + FP) e responde: “entre todos os casos que o modelo classificou como positivos, quantos realmente são positivos?”; portanto, ela é afetada pelos falsos positivos. Já o Recall é TP/(TP + FN) e responde: “entre todos os casos que realmente são positivos, quantos o modelo conseguiu encontrar?”; portanto, ele é afetado pelos falsos negativos. Imagine um modelo para detectar uma doença: se eu priorizar Recall, quero encontrar praticamente todos os pacientes que realmente estão doentes, mesmo que isso gere alguns falsos alarmes; nesse contexto, deixar uma pessoa doente passar despercebida pode ser muito mais grave do que encaminhar uma pessoa saudável para um exame adicional. Já em um sistema que dispara uma ação muito custosa quando identifica um positivo, posso priorizar Precision: quero ter alta confiança de que os casos classificados como positivos realmente sejam positivos. Por exemplo, se um sistema bloqueia automaticamente uma conta suspeita, muitos falsos positivos podem prejudicar clientes legítimos. Existe normalmente um trade-off entre as duas métricas: ao reduzir o threshold, o modelo tende a classificar mais casos como positivos, aumentando o Recall, mas também podendo aumentar os falsos positivos e reduzir a Precision; ao aumentar o threshold, acontece geralmente o contrário. Portanto, eu não escolheria Precision ou Recall olhando apenas para qual número é maior, mas sim perguntando: qual erro custa mais para o negócio, um falso positivo ou um falso negativo? Se falsos negativos forem muito graves, priorizo Recall; se falsos positivos forem muito graves, priorizo Precision; e quando ambos forem relevantes, posso usar F1-score ou analisar a curva Precision-Recall e escolher um threshold que represente o trade-off adequado ao negócio.

### 4. Como o threshold de classificação afeta Precision e Recall?

O threshold é o ponto de corte que transforma a probabilidade produzida pelo modelo em uma decisão de classe. Por exemplo, se a regressão logística atribui probabilidade de 0,7 a uma observação e o threshold é 0,5, classificamos essa observação como positiva; se aumentarmos o threshold para 0,8, ela passa a ser classificada como negativa. Quando reduzimos o threshold, o modelo fica mais “liberal” para declarar positivos: isso tende a aumentar o Recall, porque conseguimos capturar mais dos casos que realmente são positivos, mas também tende a gerar mais falsos positivos, reduzindo a Precision. Quando aumentamos o threshold, acontece o contrário: o modelo fica mais “exigente” para declarar um caso positivo, então tende a aumentar a Precision, porque os positivos previstos são mais confiáveis, mas pode deixar passar mais positivos reais, reduzindo o Recall. Imagine um modelo de detecção de fraude: com threshold 0,3, podemos capturar mais fraudes, aumentando o Recall, mas também podemos bloquear mais transações legítimas, reduzindo a Precision; com threshold 0,8, somos muito mais conservadores e bloqueamos apenas casos em que o modelo está bastante confiante, aumentando a Precision, mas podemos deixar algumas fraudes passarem. Portanto, existe um trade-off entre Precision e Recall, e o threshold deve ser escolhido de acordo com o custo dos falsos positivos e falsos negativos no negócio. O threshold não altera o que o modelo aprendeu nem as probabilidades produzidas; ele altera apenas a regra de decisão aplicada a essas probabilidades. Em uma entrevista, eu resumiria: diminuir o threshold normalmente aumenta Recall e reduz Precision; aumentar o threshold normalmente aumenta Precision e reduz Recall — e a escolha ideal depende do custo relativo dos dois tipos de erro.

### 5. O que é a curva ROC e o ROC-AUC? Como interpretar o AUC?

A curva ROC é uma forma de avaliar um classificador considerando vários thresholds possíveis, em vez de escolher apenas um threshold, como 0,5. Para cada threshold, calculamos dois valores: a True Positive Rate (TPR), que é o Recall, TP/(TP+FN), e a False Positive Rate (FPR), FP/(FP+TN). A curva ROC coloca o FPR no eixo X e o TPR no eixo Y, mostrando o trade-off entre encontrar mais positivos e gerar mais falsos positivos conforme mudamos o threshold. O ROC-AUC é a área abaixo dessa curva e resume, em um único número, a capacidade do modelo de separar as duas classes ao longo de todos os thresholds. A interpretação mais intuitiva do AUC é probabilística: um AUC de 0,8 significa aproximadamente que, se escolhermos aleatoriamente um exemplo positivo e um negativo, o modelo terá 80% de chance de atribuir uma pontuação maior ao positivo do que ao negativo. Um AUC de 1 representa separação perfeita; 0,5 representa um modelo que, em termos de ranking, não consegue distinguir as classes melhor que o acaso; e valores abaixo de 0,5 indicam que o ranking está invertido, sendo possível obter desempenho acima de 0,5 simplesmente invertendo as previsões. Um ponto importante é que o AUC não depende de um threshold específico e, portanto, é útil quando ainda estamos comparando a capacidade discriminativa dos modelos antes de definir o ponto de corte. Porém, ele não nos diz diretamente qual threshold devemos usar nem informa o custo dos erros no negócio. Além disso, em problemas com classes muito desbalanceadas, a ROC-AUC pode parecer boa mesmo quando o modelo produz muitos falsos positivos em relação ao número de positivos, situação em que a curva Precision-Recall pode ser mais informativa. Portanto, eu resumiria: a curva ROC mostra como TPR e FPR variam conforme mudamos o threshold, enquanto o ROC-AUC resume essa capacidade de discriminação; quanto mais próximo de 1, melhor a capacidade do modelo de ordenar positivos acima de negativos.

### 6. O que é a curva Precision-Recall e quando ela é mais informativa que a ROC?

A curva Precision-Recall (PR) mostra como existe um trade-off entre Precision e Recall conforme variamos o threshold de classificação: no eixo X colocamos o Recall e no eixo Y colocamos a Precision. Cada ponto da curva representa um threshold diferente, então, em vez de escolher antecipadamente um corte como 0,5, conseguimos observar como o comportamento do modelo muda quando ficamos mais ou menos rigorosos para classificar uma observação como positiva. A curva é particularmente útil quando temos classes desbalanceadas, porque a Precision leva em consideração diretamente os falsos positivos e, portanto, mostra melhor o quanto as previsões positivas são realmente confiáveis. Imagine um problema de detecção de fraude em que apenas 1% das transações são fraudulentas: um modelo pode ter uma ROC-AUC aparentemente muito boa porque consegue separar relativamente bem as classes, mas ainda assim, quando tentamos encontrar uma grande quantidade de fraudes, podemos gerar muitos falsos positivos em relação ao pequeno número de fraudes existentes. A curva Precision-Recall torna esse problema mais evidente, porque mostra diretamente quanto de Precision estamos sacrificando para obter mais Recall. Isso também explica por que ela pode ser mais informativa que a ROC em problemas de classe positiva rara, especialmente quando nosso interesse está justamente na identificação dessa classe minoritária. A métrica PR-AUC, ou área sob a curva Precision-Recall, resume o desempenho ao longo dos diferentes thresholds, mas sua interpretação é diferente da ROC-AUC e deve ser comparada considerando a prevalência da classe positiva. Portanto, eu usaria a ROC-AUC como uma visão geral da capacidade discriminativa do modelo, mas daria preferência à Precision-Recall quando a classe positiva é rara ou quando o custo e a qualidade das previsões positivas são particularmente importantes. Em resumo: ROC analisa TPR versus FPR; Precision-Recall analisa Precision versus Recall; e a curva PR costuma ser mais reveladora quando temos forte desbalanceamento e estamos interessados na classe positiva.

### 7. Como avaliar um classificador quando as classes estão fortemente desbalanceadas?

Quando as classes estão fortemente desbalanceadas, eu evitaria usar Accuracy como métrica principal, porque ela pode passar uma impressão muito enganosa. Imagine um problema em que apenas 1% dos clientes são fraudadores: um modelo que classifica todos como “não fraude” teria 99% de Accuracy, mas teria Recall igual a zero para a classe fraude, ou seja, não encontraria nenhuma fraude. Eu começaria olhando para a matriz de confusão e avaliaria principalmente Precision, Recall e F1-score, porque elas permitem entender especificamente o comportamento sobre a classe minoritária. Se o objetivo for encontrar o máximo possível de positivos, como detectar doenças ou fraudes, eu daria bastante atenção ao Recall; se falsos positivos forem muito custosos, olharia mais para Precision. Também analisaria a curva Precision-Recall e sua área, PR-AUC, que costuma ser mais informativa que ROC-AUC quando a classe positiva é rara, porque mostra diretamente o trade-off entre encontrar positivos e manter a qualidade das previsões positivas. Além disso, eu não avaliaria apenas um threshold arbitrário de 0,5: testaria diferentes thresholds e escolheria um ponto de operação de acordo com os custos de falsos positivos e falsos negativos do negócio. Por exemplo, em um sistema de fraude, talvez seja aceitável ter alguns falsos positivos para capturar uma quantidade maior de fraudes; já em uma campanha de marketing, talvez seja mais importante ter alta Precision para não desperdiçar contatos. No treinamento, também podemos utilizar class weights, oversampling da classe minoritária ou undersampling da majoritária, mas essas técnicas devem ser aplicadas corretamente, principalmente dentro do conjunto de treinamento, para evitar data leakage. Por fim, eu manteria um conjunto de teste representativo da distribuição real e avaliaria não apenas uma métrica isolada, mas um conjunto de métricas alinhado ao objetivo do negócio. Portanto, em uma entrevista, eu resumiria: em classes desbalanceadas, não confio na Accuracy isoladamente; analiso matriz de confusão, Precision, Recall, F1 e PR-AUC, ajusto o threshold de acordo com o custo dos erros e, se necessário, utilizo técnicas de balanceamento durante o treinamento.

### 8. Como você escolheria a métrica principal para um problema de negócio? Dê exemplos em que priorizaria Precision, Recall, F1 ou AUC.

Eu escolheria a métrica principal a partir do custo dos erros para o negócio, e não simplesmente pela métrica que apresentar o maior valor. Se o custo de um falso positivo for muito alto, eu priorizaria Precision, porque quero que, entre os casos classificados como positivos, uma proporção muito alta seja realmente positiva; por exemplo, em um sistema que bloqueia automaticamente uma conta bancária suspeita, não quero bloquear muitos clientes legítimos. Se o custo de um falso negativo for maior, eu priorizaria Recall, porque quero encontrar o máximo possível dos casos realmente positivos; por exemplo, em um sistema de triagem para uma doença grave, pode ser preferível encaminhar alguns pacientes saudáveis para investigação adicional a deixar pacientes doentes sem diagnóstico. Se Precision e Recall forem igualmente importantes e eu precisar de uma única métrica para equilibrá-las, utilizaria o F1-score, que é a média harmônica das duas e, portanto, penaliza situações em que uma está muito alta e a outra muito baixa. Já o AUC é mais adequado quando quero avaliar a capacidade discriminativa do modelo independentemente de um threshold específico, por exemplo, durante a comparação de diferentes modelos antes de decidir qual será o ponto de corte operacional. Se houver forte desbalanceamento e a classe positiva for rara, eu consideraria PR-AUC em vez de depender apenas do ROC-AUC, porque ela mostra melhor o trade-off entre Precision e Recall para a classe minoritária. Um ponto importante é que eu não escolheria a métrica apenas depois de olhar os resultados dos modelos, porque isso pode introduzir viés na comparação; primeiro defino o que significa um erro relevante para o negócio, depois escolho a métrica e o threshold coerentes com esse objetivo. Em um problema real, eu também poderia ter uma métrica principal e métricas de restrição: por exemplo, maximizar Recall mantendo Precision acima de 80%. Portanto, minha lógica seria: Precision quando falsos positivos são muito custosos; Recall quando falsos negativos são mais graves; F1 quando quero equilibrar os dois; e AUC quando quero avaliar a capacidade de discriminação sem fixar um threshold.
